Visual AI for marketing research

A practitioner guide to the current tools for turning images and video into data, predicting outcomes from them, and generating new ones. Each section names the best open and closed options, gives a short Python example, points to the benchmark that tracks the field, and cites a marketing paper that uses the method.

Decision guide

Embed images

An embedding turns each image into a vector of a few hundred to a few thousand numbers. Images that look alike or mean alike sit close together. Embeddings feed regressions, clustering, similarity search, and most of the methods further down this page.

Global embedding

One vector per image.

Use it as regressors, for clustering, or for nearest-neighbor search. Each model produces it differently: a CLS token, an attention-pooling head, or the mean of the patch tokens. The table below says which.

Patch embeddings

One vector per small square of the image.

A vision transformer cuts the image into 14 or 16 pixel squares. Map the patch vectors back onto the grid to show where in an ad a concept or an outcome comes from.

DINOv3: global and patch embeddings python · transformers 
import torch
from transformers import AutoImageProcessor, AutoModel
from transformers.image_utils import load_image

ckpt = "facebook/dinov3-vitb16-pretrain-lvd1689m"   # gated: accept the terms on HF, then `hf auth login`
processor = AutoImageProcessor.from_pretrained(ckpt)
model = AutoModel.from_pretrained(ckpt).eval()

inputs = processor(images=load_image("ad.jpg"), size={"height": 448, "width": 448},
                   return_tensors="pt")              # 448 px gives a 28 x 28 patch grid
with torch.inference_mode():
    out = model(**inputs)

R, p = model.config.num_register_tokens, model.config.patch_size     # 4, 16
H, W = inputs.pixel_values.shape[-2] // p, inputs.pixel_values.shape[-1] // p
global_emb = out.pooler_output                        # (1, 768): CLS token after layer norm
patches = out.last_hidden_state[:, 1 + R:, :]         # (1, H*W, 768): skip CLS + registers
patch_grid = patches.unflatten(1, (H, W))             # (1, H, W, 768) for heatmaps
SigLIP 2: zero-shot scores for your own labels python · transformers 
import torch
from transformers import AutoModel, AutoProcessor
from transformers.image_utils import load_image

ckpt = "google/siglip2-so400m-patch16-384"
model = AutoModel.from_pretrained(ckpt).eval()
processor = AutoProcessor.from_pretrained(ckpt)

labels = ["a photo of a luxury watch", "a photo of a sneaker", "a photo of a family dinner"]
inputs = processor(text=labels, images=load_image("ad.jpg"),
                   padding="max_length", max_length=64, return_tensors="pt")
with torch.inference_mode():
    out = model(**inputs)

img_emb = out.image_embeds                 # (1, d), unit length: the global embedding
cos = img_emb @ out.text_embeds.T          # rank labels by cosine similarity
probs = torch.sigmoid(out.logits_per_image)  # one independent probability per label (not softmax)

Use embeddings as regressors

An embedding has hundreds of columns, so ordinary least squares overfits on a few thousand images. Use ridge or lasso for a continuous outcome and penalized logistic regression for a class, with the penalty chosen by cross-validation. Normalize vectors to unit length before cosine similarity or clustering. PCA to 50 to 100 components helps when you need a few controls; keep UMAP for plots. If an embedding-based prediction enters a second-stage causal regression, it is a generated regressor, so see inference with predicted variables.

Heatmaps from patch embeddings

Start from the patch grid with the CLS and register tokens removed. There are three ways to turn it into a map.

  1. Similarity to a reference (DINOv3). Compute the cosine similarity of every patch to a chosen patch or to a reference image such as the brand logo, then upsample the grid to the image size.
  2. Similarity to a text (TIPSv2, or dino.txt for DINOv3). Take the dot product of each normalized patch with a normalized text embedding. Compare maps across texts; the absolute level means little.
  3. Outcome map from a linear probe (DINOv3). Regress the outcome on the mean of each image's patch tokens, then apply the fitted weights to each patch. Because the mean is linear, the patch scores average exactly to the prediction, so the map is an additive decomposition of it. This holds for the mean of the patches and not for the CLS token.
Outcome heatmap from a linear probe python · scikit-learn 
import numpy as np
from sklearn.linear_model import RidgeCV

# P: one (H*W, d) array of DINOv3 patch tokens per image, from the snippet above
# y: the outcome for each image, such as log click-through rate
X = np.stack([p.mean(axis=0) for p in P])                  # mean-pooled patches, (n, d)
probe = RidgeCV(alphas=np.logspace(-2, 4, 25)).fit(X, y)

heat = (P[0] @ probe.coef_).reshape(H, W)   # per-patch contribution for image 0
# heat.mean() + probe.intercept_ equals the prediction for image 0.
# Upsample heat to the image size (bilinear) and overlay it on the ad.

Label images with a VLM

A vision-language model (VLM) reads an image and answers a question about it in text. Give it the question you would give a research assistant, such as "Does this ad show a person using the product?", and you get a label for every image with no training. Use it for concepts a person can define and check. It cannot predict market outcomes it has never seen.

A labeling workflow that survives review

  1. Write a codebook: the question, the allowed answers, and two or three edge cases.
  2. Pilot the prompt on 50 images and revise the codebook, not the images.
  3. Run every image with greedy decoding (no sampling) and log the model ID and date.
  4. Hand-code a random sample of about 400 images and report agreement. With a balanced binary label and 85% agreement, 400 images give a kappa near 0.70 with a 95% interval of about ±0.07.
  5. If the labels enter a regression, correct for their errors with the methods below.
Zero-shot labels with an open VLM python · transformers 
from transformers import AutoProcessor, AutoModelForMultimodalLM

MODEL_ID = "Qwen/Qwen3.5-9B"          # "Qwen/Qwen3.8-27B" on a larger GPU
processor = AutoProcessor.from_pretrained(MODEL_ID)
model = AutoModelForMultimodalLM.from_pretrained(MODEL_ID, dtype="auto", device_map="auto")

LABELS = ["lifestyle", "product-only", "text-heavy", "other"]
PROMPT = ("Classify this ad image into exactly one category: "
          + ", ".join(LABELS) + ". Answer with the category name only.")

def label_image(path):
    messages = [{"role": "user", "content": [
        {"type": "image", "path": path},
        {"type": "text", "text": PROMPT}]}]
    inputs = processor.apply_chat_template(
        messages, add_generation_prompt=True, tokenize=True, return_dict=True,
        return_tensors="pt", enable_thinking=False,   # no reasoning trace
    ).to(model.device)
    out = model.generate(**inputs, max_new_tokens=10, do_sample=False)   # greedy: reproducible
    text = processor.decode(out[0][inputs["input_ids"].shape[-1]:], skip_special_tokens=True)
    return next((l for l in LABELS if l in text.lower()), "unparsed")

Why the ladder starts with frozen embeddings

We found no published study that compares these approaches on image regression. The closest evidence is object classification on ImageNet with 1.28 million labels. There, a fine-tuned VLM beat a linear probe on its own vision encoder by only 0.5 to 1.5 points (Zhang et al. 2024). Marketing datasets are far smaller and their outcomes are noisier. Training a VLM to write numbers as text also pulls predictions toward the middle of long-tailed outcomes such as likes and views (Du et al. 2026). The label thresholds above are judgment calls. Run any richer model on the same cross-fitting folds as step 1 and report both.

Step 1: frozen embeddings and cross-fitted ridge python · transformers + scikit-learn 
import numpy as np, torch
from PIL import Image
from transformers import AutoImageProcessor, AutoModel
from sklearn.linear_model import RidgeCV
from sklearn.model_selection import KFold, cross_val_predict

MODEL_ID = "facebook/dinov3-vitl16-pretrain-lvd1689m"   # gated: accept the licence on HF
processor = AutoImageProcessor.from_pretrained(MODEL_ID)
model = AutoModel.from_pretrained(MODEL_ID, device_map="auto").eval()

@torch.inference_mode()
def embed(paths, bs=32):
    out = []
    for i in range(0, len(paths), bs):
        imgs = [Image.open(p).convert("RGB") for p in paths[i:i + bs]]
        x = processor(images=imgs, return_tensors="pt").to(model.device)
        out.append(model(**x).pooler_output.float().cpu().numpy())
    return np.vstack(out)

X = embed(image_paths)                       # n x 1024
y = np.log1p(likes)                          # long-tailed outcome on the log scale
folds = KFold(5, shuffle=True, random_state=0)
yhat = cross_val_predict(RidgeCV(alphas=np.logspace(-2, 4, 25)), X, y, cv=folds)
print("out-of-fold R2:", 1 - ((y - yhat) ** 2).sum() / ((y - y.mean()) ** 2).sum())
# Carry the out-of-fold yhat into any second-stage regression, never in-sample fits.

Parameter-efficient fine-tuning

Parameter-efficient fine-tuning (PEFT) freezes the pretrained model and trains a small add-on, so a 9B model fits on one GPU and the adapter file is a few hundred megabytes. Plain LoRA on all linear layers is the standard. LoRA matches full fine-tuning on small and medium datasets when it targets every layer and uses a learning rate about 10 times the full fine-tuning rate (LoRA Without Regret).

Getting a number out of a VLM

No library documents an image-to-number VLM pipeline from end to end. There are three workable patterns.

  • For a bounded rating, such as a 1 to 7 scale, train the model on level words and read off the probability-weighted average, as Q-Align does for image quality.
  • For a count or a log count, put a regression head on the last hidden state. In transformers, Qwen3_5ForSequenceClassification with num_labels=1 does this and accepts images.
  • As the cheapest check, take the VLM's hidden states as frozen features and fit ridge, as in step 1.

Explain the predictions

Referees expect a heatmap for each main model and a check that it is not noise (Adebayo et al. 2018). For step 1, the patch-probe map is exact. For any model, occlusion grays out one patch at a time and records how the prediction moves (Captum Occlusion). Grad-CAM and Integrated Gradients need gradients (pytorch-grad-cam, Captum). VLM attention maps and the model's own rationales are not faithful explanations. Bright background patches in ViT maps can be artifacts (Darcet et al. 2024).

Inference with predicted variables

Every tool above produces predictions, and predictions have errors. When a predicted label, score, or index enters a regression, those errors bias the coefficient and make its standard error too small. The classifier's accuracy does not tell you by how much. The fix is a small random sample coded by people and an estimator that uses it.

The workflow is the same whichever tool made the prediction.

  1. Draw a random sample of images, typically a few hundred, with known sampling probabilities.
  2. Have people code the variable on that sample, using the same definition the model was given.
  3. Run the model on every image, including the coded sample.
  4. Estimate your regression with one of the corrections below. It uses the coded sample to measure and remove the prediction error.

If you trained the predictor yourself, keep the images that trained it out of the regression sample, or cross-fit.

Read the licence before you pick an open model

Most top open image models are not licensed for commercial use. Qwen-Image-2.1 allows research and evaluation only. FLUX.2 [dev], FLUX 3 Klein, and Ideogram 4.0 (open weights, gated) are non-commercial. MiniMax H3-Image ranks first among open models, but its licence excludes the United States, the EU, the UK, and South Korea. A LoRA trained on a model inherits that model's licence, so train on an Apache 2.0 base such as FLUX.2 [klein] 4B if a brand partner will use the outputs.

Fine-tune a generator on your own products

LoRA (low-rank adaptation) freezes the generator and trains a small add-on file. DreamBooth-LoRA ties one subject, such as a product or a mascot, to a rare token in the prompt; it usually needs 5 to 30 images of the subject. A style LoRA trains on a few hundred captioned images. Train on the non-distilled base checkpoint where the maker ships one.

Four maintained trainers support Qwen-Image and FLUX.2: the diffusers DreamBooth scripts (the most transparent for a Python user), ai-toolkit (the quickest to run, with a web UI), SimpleTuner, and musubi-tuner.

Design notes for stimuli

  • To change one attribute and hold the rest fixed with an open model, reuse the same seed and initial latents and change only the prompt or the LoRA scale. Closed APIs give you no control over the noise.
  • An instruction edit ("make the bottle green") can also change pixels outside the target. Measure the change outside the edited region and report it as a manipulation check.
  • Closed models disappear. Google shut down Imagen 4 on the Gemini API on 17 August 2026. Generate the full stimulus set once, archive the files with their prompts, the model ID, and the date, and use open weights with a saved checkpoint if a referee may ask for new stimuli.
  • Gemini images carry a SynthID watermark, and OpenAI states that its images carry C2PA metadata. Open-weights pipelines add no provenance signal. For field work shown to EU consumers, Article 50 of the EU AI Act requires machine-readable marking of generated images.
  • Evidence that generated stimuli work: in Hartmann, Exner, and Domdey (2025, IJRM), AI-generated marketing images matched or beat human-made ones in 254,400 evaluations. The models in that study are now two generations old.

Why the open list is not the leaderboard's open list

MiniMax H3 is the best open-weights video model on both arenas, and its two derivatives rank next. Its licence bars use in the United States, the EU, the UK, and South Korea, so this guide lists the three open models most readers can legally run. All three rank well below the closed models. Wan has open weights only up to version 2.2; Wan 2.5 and later are API-only.

Closed video APIs change fastest. Google shut down the Veo 3.1 preview models on the Gemini API on 22 October 2026, and OpenAI shut down the Sora 2 API on 24 September 2026 with no replacement.

To fine-tune an open video model on your own footage, use DiffSynth-Studio, musubi-tuner, ai-toolkit, or diffusion-pipe. diffusers loads video LoRAs but has no training script for Wan or HunyuanVideo.

    negative_prompt="",          # the model card gives a long default negative prompt
    height=704, width=1280, num_frames=121,   # 121 frames is about 5 s at 24 fps

).frames[0]

Analyze videos you already have

There are three ways to turn a video into data, from richest to cheapest.

  1. Send the whole video to a long-context multimodal model and ask coded questions: is the product shown, when does the brand first appear, what claims are spoken. Gemini reads video with its audio at 1 frame per second by default, so raise the rate for fast-cut ads.
  2. Embed the clip with a video embedding model, which captures motion that a frame average misses. The vector goes into a regression, clustering, or similarity search.
  3. Sample frames, embed each one with an image model, and average them. This is cheap and reproducible, and it ignores audio and motion. Keep the frame-level vectors if timing matters.

Treat answers from option 1 as measurements with error: code a validation sample by hand and use the inference corrections below.

Three habits keep a study reproducible while the models change.

  • Record the exact model ID or checkpoint, the library version, and the date for every model you use. Hugging Face pages show a commit hash; cite it.
  • Archive every output the paper depends on: embeddings, labels, generated images and videos. Closed models are retired on short notice, and in 2026 that happened to Imagen 4, Veo 3.1 preview, and Sora 2.
  • Prefer open weights for any measurement a referee may ask you to rerun or extend.

More tools

Specialized tools for measuring specific things in an image: where an object is and how much of the frame it covers, what text the ad contains, whether a face looks at the camera, and where viewers are likely to look. They are useful for building interpretable features and controls, but most projects need the core guide first.

A VLM or a specialist?

A VLM asked for JSON ({"has_person": true, "n_people": 2, "price": "4.99"}) does well on categorical codes, small counts, and text in ads. It still trails specialist tools on anything measured in pixels. On the ODinW-13 detection benchmark, Qwen3-VL scores 48.6 against 61.0 for SAM 3. Use a VLM for codes and a specialist for boxes, masks, and areas. Either way, validate on a hand-coded sample.

Detect and segment objects

Detection draws a box around each instance of a named thing, such as a logo, a person, or a bottle. Segmentation gives its exact outline. From the outline you can compute area share, the fraction of the frame the object covers. Text-prompted models work with no training. Detectors fine-tuned on a few hundred of your own labeled images are faster and more accurate on unusual images.

Area share of logos, people, and products python · transformers 
import torch
from PIL import Image
from transformers import Sam3Model, Sam3Processor

model = Sam3Model.from_pretrained("facebook/sam3", device_map="auto")   # gated: accept the licence
processor = Sam3Processor.from_pretrained("facebook/sam3")
image = Image.open("ad.jpg").convert("RGB")

for concept in ["logo", "person", "bottle"]:
    inputs = processor(images=image, text=concept, return_tensors="pt").to(model.device)
    with torch.no_grad():
        outputs = model(**inputs)
    res = processor.post_process_instance_segmentation(
        outputs, threshold=0.5, mask_threshold=0.5,
        target_sizes=inputs.get("original_sizes").tolist())[0]
    masks = res["masks"]                       # (n_instances, H, W)
    share = masks.any(dim=0).float().mean().item() if len(masks) else 0.0
    print(f"{concept}: {len(masks)} found, area share {share:.3f}")

Aesthetics and low-level features

Aesthetic scorers predict how photography-contest raters would rate an image, so a high score does not mean an ad persuades. OneAlign (Q-Align) is the strongest documented scorer (MIT licence, Spearman 0.82 on the AVA benchmark). pyiqa puts dozens of quality metrics behind one API under a non-commercial licence. For transparent pixel statistics, pyaesthetics computes brightness, Hasler and Süsstrunk colorfulness, and visual complexity, and visual-clutter computes Feature Congestion clutter. Cite the original measures, such as Pieters, Wedel, and Batra (2010, Journal of Marketing) for visual complexity in ads. Resize and re-encode every image the same way before comparing file-size measures.

To extract many of these at once, Image Analyzer (Exner, Konrad, and Hartmann 2025) computes 49 image metrics through a notebook, an app, or Python.
