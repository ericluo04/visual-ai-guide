Decision guide

Embed images

An embedding turns each image into a vector of a few hundred to a few thousand numbers. Images that look alike or mean alike sit close together. Embeddings feed regressions, clustering, similarity search, and most of the methods further down this page.

Global embedding: one vector per image

The whole ad becomes one list of numbers. Use it as regressors, to cluster ads, or to find the most similar images.

Patch embeddings: one vector per square

The ad is cut into small squares, and each square gets its own vector. Score the squares and you get a map of where something is in the ad.

How the two connect: most image models today are vision transformers. A vision transformer cuts the image into squares of 14 or 16 pixels, called patches, and adds one extra summary token, often called the CLS token. After the model has read the image, the summary token (or the average of all the patches) is the global embedding, and the patches are the patch embeddings.

DINOv3: global and patch embeddings python · transformers 
import torch
from transformers import AutoImageProcessor, AutoModel
from transformers.image_utils import load_image

ckpt = "facebook/dinov3-vitb16-pretrain-lvd1689m"   # gated: accept the terms on HF, then `hf auth login`
processor = AutoImageProcessor.from_pretrained(ckpt)
model = AutoModel.from_pretrained(ckpt).eval()

inputs = processor(images=load_image("ad.jpg"), size={"height": 448, "width": 448},
                   return_tensors="pt")              # 448 px gives a 28 x 28 patch grid
with torch.inference_mode():
    out = model(**inputs)

R, p = model.config.num_register_tokens, model.config.patch_size     # 4, 16
H, W = inputs.pixel_values.shape[-2] // p, inputs.pixel_values.shape[-1] // p
global_emb = out.pooler_output                        # (1, 768): CLS token after layer norm
patches = out.last_hidden_state[:, 1 + R:, :]         # (1, H*W, 768): skip CLS + registers
patch_grid = patches.unflatten(1, (H, W))             # (1, H, W, 768) for heatmaps

probs = torch.sigmoid(out.logits_per_image)  # one independent probability per label (not softmax)

Use embeddings in a regression

An embedding has hundreds or thousands of columns, often more than you have images, so ordinary least squares breaks down. Use a high-dimensional regression that shrinks or selects coefficients. Common choices are ridge, lasso, and elastic net, with the amount of shrinkage chosen by cross-validation. Bayesian versions such as spike-and-slab or horseshoe priors do the same job and give full uncertainty. Use the logistic versions for a yes or no outcome.

Be careful with squeezing the embedding into a handful of principal components (PCA). PCA keeps the directions where images vary most, and those need not be the ones that matter for your outcome. A few linear directions can also lose much of what a nonlinear model encoded.

Often the image is a control and the question is about something else: the effect of price, a promotion, or a model's face in the ad. A growing literature treats images as confounders directly. Imai and Nakamura (2026, PNAS) read a compact summary of each image from inside the generative model that made it, then adjust for that summary with machine learning, so the effect of one image feature is not credited to features that tend to appear with it. Their paper points to further work, such as DoubleMLDeep (Klaassen et al. 2024), which runs double machine learning with image and text controls.

Effect of price, with the image embedding as a control python · econml 
# pip install econml
from sklearn.linear_model import LassoCV

Heatmaps from patch embeddings

A heatmap gives each square of the image a score and colors it. What the score means depends on what you compare each square with. There are three common choices.

  1. Compare each square with a reference image, such as your logo (DINOv3). Squares that look like the logo light up.
  2. Compare each square with a phrase, such as "a bottle" (TIPSv2, or dino.txt for DINOv3). Squares that match the phrase light up. Compare maps across phrases; the raw level means little.
  3. Score each square by its contribution to an outcome (DINOv3). Fit a regression of the outcome on the average of each image's patch embeddings, then apply the fitted coefficients to each square. The square scores average exactly to the image's prediction, so the map splits the prediction across the ad.
Outcome heatmap from a linear probe python · scikit-learn 
import numpy as np
from sklearn.linear_model import RidgeCV

# P: one (H*W, d) array of DINOv3 patch tokens per image, from the snippet above
# y: the outcome for each image, such as log click-through rate
X = np.stack([p.mean(axis=0) for p in P])                  # mean-pooled patches, (n, d)
probe = RidgeCV(alphas=np.logspace(-2, 4, 25)).fit(X, y)

heat = (P[0] @ probe.coef_).reshape(H, W)   # per-patch contribution for image 0
# heat.mean() + probe.intercept_ equals the prediction for image 0.
# Upsample heat to the image size (bilinear) and overlay it on the ad.

Label images with a VLM

A vision-language model (VLM) reads an image and answers a question about it in text. Give it the question you would give a research assistant, such as "Does this ad show a person using the product?", and you get a label for every image with no training. Use it for concepts a person can define and check. It cannot predict market outcomes it has never seen.

A labeling workflow

The workflow below follows the split-sample framework of Egami, Fong, Grimmer, Roberts, and Stewart (2022, Science Advances). Their paper is about text, and the same logic carries over to images: develop the measure on one part of the data and use it, unchanged, on another.

  1. Split your images at random into a development set and a held-out set. Set the held-out set aside.
  2. On the development set, write a codebook: the question, the allowed answers, and two or three edge cases. Revise the prompt as often as you like here.
  3. Freeze the prompt and the model version. Run the model on the held-out images and set it to always give its single most likely answer (greedy decoding), so a rerun gives the same labels. Log the model ID and date.
  4. Hand-code a random sample of about 400 held-out images and report how often people and the model agree. With a yes or no label split evenly and 85% agreement, 400 images give a kappa near 0.70, give or take 0.07.
  5. If the labels enter a regression, correct for their errors with the methods below.
Label ads with an open VLM python · transformers 
from transformers import AutoProcessor, AutoModelForMultimodalLM

MODEL_ID = "Qwen/Qwen3.5-9B"          # "Qwen/Qwen3.8-27B" on a larger GPU
processor = AutoProcessor.from_pretrained(MODEL_ID)
model = AutoModelForMultimodalLM.from_pretrained(MODEL_ID, dtype="auto", device_map="auto")

LABELS = ["lifestyle", "product-only", "text-heavy", "other"]
PROMPT = ("Classify this ad image into exactly one category: "
          + ", ".join(LABELS) + ". Answer with the category name only.")

def label_image(path):
    messages = [{"role": "user", "content": [
        {"type": "image", "path": path},
        {"type": "text", "text": PROMPT}]}]
    inputs = processor.apply_chat_template(
        messages, add_generation_prompt=True, tokenize=True, return_dict=True,
        return_tensors="pt", enable_thinking=False,   # no reasoning trace
    ).to(model.device)
    out = model.generate(**inputs, max_new_tokens=10, do_sample=False)   # greedy: reproducible
    text = processor.decode(out[0][inputs["input_ids"].shape[-1]:], skip_special_tokens=True)
    return next((l for l in LABELS if l in text.lower()), "unparsed")

Step 1 is the embeddings-plus-regression recipe from Embed images, scored out of sample. Fit the regression on part of the data, predict the rest, and rotate (cross-fitting), so every image gets a prediction from a model that never saw it.

Step 1: embeddings and a cross-fitted regression python · transformers + scikit-learn 
import numpy as np, torch
from PIL import Image
from transformers import AutoImageProcessor, AutoModel
from sklearn.linear_model import RidgeCV
from sklearn.model_selection import KFold, cross_val_predict

MODEL_ID = "facebook/dinov3-vitl16-pretrain-lvd1689m"   # gated: accept the licence on HF
processor = AutoImageProcessor.from_pretrained(MODEL_ID)
model = AutoModel.from_pretrained(MODEL_ID, device_map="auto").eval()

@torch.inference_mode()
def embed(paths, bs=32):
    out = []
    for i in range(0, len(paths), bs):
        imgs = [Image.open(p).convert("RGB") for p in paths[i:i + bs]]
        x = processor(images=imgs, return_tensors="pt").to(model.device)
        out.append(model(**x).pooler_output.float().cpu().numpy())
    return np.vstack(out)

X = embed(image_paths)                       # n x 1024
y = np.log1p(likes)                          # long-tailed outcome on the log scale
folds = KFold(5, shuffle=True, random_state=0)
yhat = cross_val_predict(RidgeCV(alphas=np.logspace(-2, 4, 25)), X, y, cv=folds)
# Swap RidgeCV for LassoCV or ElasticNetCV; for horseshoe or spike-and-slab priors use PyMC or R's brms.
print("out-of-fold R2:", 1 - ((y - yhat) ** 2).sum() / ((y - y.mean()) ** 2).sum())
# Carry the out-of-fold yhat into any second-stage regression, never in-sample fits.

Fine-tune a model on your own data

Retraining a whole model means updating billions of numbers inside it, which takes more computing power and data than most research projects have. Parameter-efficient fine-tuning (PEFT) leaves the original model as it is and learns a small set of extra adjustments on top. The update fits on one GPU and is saved as a small file next to the model.

The most common PEFT method is LoRA (low-rank adaptation), and plain LoRA applied to every layer is a good default. It matches full retraining on small and medium datasets when it uses a learning rate about 10 times higher (LoRA Without Regret). The variants in the table change how the adjustments are set up or stored, and you can try them with one setting each.

MethodWhat it doesSetting in Hugging Face PEFT
LoRAAdds a small, compact adjustment to each layer of the model.LoraConfig
QLoRALoRA on a compressed copy of the model, so a larger model fits on one GPU. Unsloth advises against it for Qwen3.5.bitsandbytes 4-bit + LoraConfig
DoRASplits each adjustment into a size and a direction, which is often a little more accurate.use_dora=True
rsLoRARescales the adjustment so that larger adapters still train smoothly.use_rslora=True
PiSSAStarts the adjustment from the most important directions in the original model, so training settles faster.init_lora_weights="pissa"
LoRA+Trains one half of the adjustment faster than the other.create_loraplus_optimizer

The easiest start on one GPU is a ready-made notebook from Unsloth (Qwen3.5 4B, Gemma 4 E4B): open it and swap in your own images and labels. TRL is the standard Hugging Face library for the same job, LLaMA-Factory runs from a config file or web UI, and ms-swift has command-line flags for classification and regression heads.

Getting a number out of a VLM

A VLM normally answers in words, so predicting a number such as a click-through rate takes extra setup. No library covers this from start to finish yet. There are four workable patterns.

  • Prompt the model to choose one answer from a fixed set of labels, which can be numbers such as 1 to 7. This gives a single classified label for each image, and the model's probability for each label is available too, with no training needed. Li and Wagle (2026) show that general-purpose models already work well this way and when fine-tuning still helps.
  • For a bounded rating, such as a 1 to 7 scale, teach the model to answer with level words ("bad" through "excellent") and average the levels by how confident the model is in each, as Q-Align does for image quality.
  • For a count or a log count, add a small output layer that returns a number instead of words (a regression head). In transformers, Qwen3_5ForSequenceClassification with num_labels=1 does this and accepts images.
  • As the cheapest check, take the VLM's internal representation of each image as an embedding and use step 1.

Explain the predictions

A heatmap shows which parts of an image pushed a prediction up or down. You can interpret your models with post-hoc methods from interpretable machine learning.

  • Captum implements the widely accepted methods for PyTorch models, including Integrated Gradients, Grad-CAM, saliency maps, occlusion, and Shapley value sampling. Check that the maps are not noise with the sanity checks of Adebayo et al. (2018): a map that barely changes when the model's weights are randomized is not explaining the model.
  • Do not read a VLM's attention maps or its written reasons as explanations; neither reliably reflects what drove the answer. Bright background squares in transformer maps can be artifacts (Darcet et al. 2024).

Inference with predicted variables

Every tool above produces predictions, and predictions have errors. When a predicted label, score, or index enters a regression, those errors bias the coefficient and make its standard error too small. The classifier's accuracy does not tell you by how much. The fix is a small random sample coded by people and an estimator that uses it.

The workflow is the same whichever tool made the prediction.

  1. Draw a random sample of images, typically a few hundred, with known sampling probabilities.
  2. Have people code the variable on that sample, using the same definition the model was given.
  3. Run the model on every image, including the coded sample.
  4. Estimate your regression with one of the corrections below. It uses the coded sample to measure and remove the prediction error.

If you trained the predictor yourself, keep the images that trained it out of the regression sample, or cross-fit.

Fine-tune a generator on your own products

You can teach an open model what your product or brand style looks like. The standard tool is LoRA, the same small add-on described in Predict outcomes: the original model stays untouched, and a small file learns your product from your own photos.

  • To teach one product or mascot, use about 5 to 30 photos of it and a made-up name for it, such as "sks bottle". The model learns to draw the product whenever that name appears in a prompt. This recipe is called DreamBooth.
  • To teach a visual style, use a few hundred images, each with a short caption.
  • Some makers release two versions of a model: a fast version that has been simplified for quick generation, and the full "base" version. Train on the base version when there is one.

Four maintained training tools support Qwen-Image and FLUX.2. ai-toolkit is the quickest to start and has a point-and-click interface. The diffusers DreamBooth scripts show every step in Python. SimpleTuner and musubi-tuner cover the most models.

Design notes for stimuli

  • An image generator starts every picture from random noise, and a number called the seed fixes that noise. To change one attribute and hold everything else fixed, keep the seed the same and change only the prompt or the strength of your LoRA. Closed APIs do not let you fix the seed.
  • Asking a model to edit an image ("make the bottle green") can also change things you did not ask for. Measure how much the rest of the image changed and report it as a manipulation check.
  • Closed models are retired without much notice. Generate the full stimulus set once and archive the files with their prompts, the model name, and the date. If you may need new stimuli later, use an open model and keep a copy of it.
  • Gemini images carry a hidden SynthID watermark, and OpenAI states that its images carry C2PA content credentials. Open models add no marking. For field studies shown to EU consumers, Article 50 of the EU AI Act requires that generated images be marked in a machine-readable way.

Embed/analyze videos

Turn videos you already have, such as ads, short-form posts, and livestreams, into data. The same two moves as for images apply: ask a model coded questions, or turn each video into an embedding.

There are three ways to turn a video into data, from richest to cheapest.

  1. Send the whole video to a multimodal model and ask coded questions: is the product shown, when does the brand first appear, what claims are spoken. Gemini watches the video and listens to its audio. It looks at 1 frame per second by default, so raise the rate for fast-cut ads.
  2. Turn each clip into one embedding with a video embedding model. It captures motion that a single frame misses. The vector then goes into a regression, clustering, or similarity search, as in Embed images.
  3. Take a frame every second or so, embed each frame with an image model, and average them. This is cheap and reproducible but ignores sound and motion. Keep the frame-level vectors if timing matters.

Treat answers from the first approach as measurements with error. Follow the labeling workflow and the inference corrections.

Three habits keep a study reproducible while the models change.

More tools

Specialized tools for measuring specific things in an image: where an object is and how much of the frame it covers, what text the ad contains, whether a face looks at the camera, and where viewers are likely to look. They are useful for building interpretable features and controls, but most projects need the core guide first.

A VLM or a specialist?

You can ask a VLM to answer several questions about an image at once and return the answers as named fields (JSON), for example whether a person appears, how many people there are, and the price shown: {"has_person": true, "n_people": 2, "price": "4.99"}. VLMs answer this kind of question well when the answer is a category, a small count, or text printed in the ad. They do worse than specialist tools when the answer is measured in pixels, such as where an object sits or how much of the image it covers. On the ODinW-13 detection benchmark, Qwen3-VL scores 48.6 and SAM 3 scores 61.0. Use a VLM for codes and a specialist tool for boxes, masks, and areas. Either way, check the output against a hand-coded sample.

Detect and segment objects

Detection draws a box around each instance of a named thing, such as a logo, a person, or a bottle. Segmentation gives its exact outline. From the outline you can compute area share, the fraction of the frame the object covers. Text-prompted models work with no training. Detectors fine-tuned on a few hundred of your own labeled images are faster and more accurate on unusual images.

import torch
from PIL import Image
from transformers import Sam3Model, Sam3Processor

model = Sam3Model.from_pretrained("facebook/sam3", device_map="auto")   # gated: accept the licence
processor = Sam3Processor.from_pretrained("facebook/sam3")
image = Image.open("ad.jpg").convert("RGB")

for concept in ["logo", "person", "bottle"]:
    inputs = processor(images=image, text=concept, return_tensors="pt").to(model.device)
    with torch.no_grad():
        outputs = model(**inputs)
    res = processor.post_process_instance_segmentation(
        outputs, threshold=0.5, mask_threshold=0.5,
        target_sizes=inputs.get("original_sizes").tolist())[0]
    masks = res["masks"]                       # (n_instances, H, W)
    share = masks.any(dim=0).float().mean().item() if len(masks) else 0.0
    print(f"{concept}: {len(masks)} found, area share {share:.3f}")

R and SPSS tutorials for coding open-ended responses with an LLM, a hosted coding app, notes on API costs and data privacy, and sample preregistrations for validating LLM coding. The site covers text, but its validation logic carries over to images.

Image metrics pipeline

Image Analyzer, from Exner, Yannick, Maximilian Konrad, and Jochen Hartmann (2025). "Image Analyzer: A Framework and Pipeline to Analyze Image Metrics." SSRN 5776702

Open-source code that extracts 49 image metrics in eleven groups, from color and composition to human presence, text, and generated descriptions. Runs as a Colab notebook, a no-code app, or Python. AGPL-3.0.
